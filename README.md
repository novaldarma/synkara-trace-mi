# SYNKARA TRACE-MI · CALIBER 2026 Case 2

English-language demonstration of Manufacturing Intelligence. Five source pages reproduce the provided records; Overview and analysis pages combine validated indicators, historical replay, an external electricity forecast, evidence review, and owner-tracked demo actions. Investigate keeps incident filters on return and separates historical observations from retrospective conclusions. Actions now records the reason, source evidence, expected result, human decision, demo progress, completion review, and full audit history.

## Run the project

1. Install Node 24+ and run `npm ci` in this folder.
2. Copy `.env.example` to `.env.local`, save it as UTF-8 without BOM, and set the **real** Supabase Project URL and **publishable** key from Project Settings. The URL must look like `https://<project-ref>.supabase.co`. Never paste a database password, service key, or AI key in a `VITE_PUBLIC_` variable. Run `npm run check:config` to verify the format without printing the values.
3. Run `npm run dev` and open the displayed local URL. `npm run build` builds the deployable frontend.
4. Read `docs/DEPLOYMENT_READINESS.md` **before changing a live database**. The September 29 read-only audit found the dev project's migration ledger differs from the objects already installed: 009–012 are not individually listed, even though their working objects and mappings exist after a reconciliation entry. Never rerun `db push --include-all`, copy SQL into the Editor, or mark migrations applied just to align history. Compare schema, policies, source counts and the ledger under the specific target project first. The reference project is a frozen source baseline; the Vite application does not deploy schema changes.
5. Use **one shared judge account** for the full experience. Create the email/password once in Supabase Auth, then enroll its user UUID in `app_memberships` with `access_level='judge'` and `is_active=true` through an administrator-controlled SQL session. This internal label does not create a separate judge UI or restrict features by category. Never put the password in code or this ZIP. Case 2 tables require the active membership and RLS; the fictional public examples are collapsed below the sign-in form.

The shared account can create, accept, and advance its own demo actions. The owner is that same demo account; the audit trail cannot identify which individual judge clicked a button. For real operations, named engineer accounts, approval roles, and attribution would be required. Existing actions from other accounts do not appear in the judge account's task list. This prototype records desk-review or simulated work only. A verified demo action does not prove physical maintenance, avoided loss, or independent engineer sign-off.

`npm run dev` also serves `/api/assistant` locally, using the same handler as the Vercel function. Set `TRACE_AI_PROVIDER=fireworks`, `FIREWORKS_API_KEY`, and `FIREWORKS_MODEL` in `.env.local` to enable live retrospective drafts, then restart Vite. Keep provider keys **server-only** and configure the same server-side variables on Vercel. If the configured AI provider is unavailable, retrospective mode returns a deterministic source summary. Pre-event replay always uses its deterministic cutoff-safe summary. Source facts and exact original-row/column links remain visible separately from generated wording. Never place an AI key in a `VITE_PUBLIC_` variable or send a whole source file to the provider.

## Five demonstration checks

1. Filter Overview by plant and occurrence date. All incident totals, distribution bars, and the featured highest-actual-loss case must reflect the selection. Expand the source rule, open the incident, and check the original row. The Overview shows rounded US$ amounts with exact US$ amounts underneath. The optional **Generate AI explanation** uses the same server function as Evidence Assistant; without the function it reports availability and leaves the source-backed review intact. Open **Data foundation** to see definition/version, source-column mapping and unresolved data issues.
2. Open Investigate → **Rewind asset observations**, select KO-3201 and 22 April 2026. The latest Equipment row must show `ALARM`, 71.674 micron radial vibration and 1,372.791 ppm oil water. Use **Open this exact Condition History row** to check the highlighted source record. Production MM/S remains in a different panel. No future incident or RCA enters this replay. At a 29 April cutoff the separate weekly status is `TRIP` and the inspection candidate must also appear; a cutoff after the incident is not labeled “pre-event.”
3. Open **Investigate → Review recorded incidents → Try KO-3201 · 29 Apr** and inspect its 32 hours of downtime and US$1.58M rounded actual loss (exactly 1,584 thousand USD in the source). Follow the link to Excel Incident Database row 5; rewind to the last weekly record strictly before this incident; inspect the selected RCA deck under its visual-review warning. Its generic shared equipment type does not establish a similar failure. Select **Draft a follow-up**. Review the evidence snapshot, write a specific step, rationale, and expected result. Save the draft, then accept it with a reason, responsible function, review priority rationale, and future due date. Start the demo follow-up, submit a checkable desk-review or explicitly simulated result, and verify or return it for more work. Reload after each stage to see the saved audit history. Try the reject, cancel, and reschedule routes on separate drafts as needed. Search, status filter, and pagination in Actions cover the complete saved-action list. The shared judge account is automatically the demo owner and also records the review; its audit trail does not identify a separate person.
4. Open another incident without one of the five supplied RCA documents. It must say `RCA not supplied in competition baseline` and avoid declaring a confirmed cause.
5. From Overview open the separately labeled **Energy forecast** example, choose several UCI cutoffs, inspect four kWh predictions and reveal the test actual for the selected cutoff through the guarded RPC. Each revealed interval links to its exact original CSV row and `Usage_kWh` column. The separate Energy page estimates variable cost in US$ using a *published 2018 national industrial electricity price* (106.46 KRW/kWh) divided by a *published 2018 annual average exchange rate* (1,099.2926 KRW/US$). It shows both sources and does not call the result a facility tariff, bill, or saving. A missing RPC withholds the observed result and must be repaired in the database deployment. Inspect the broad distribution of absolute errors as well as the small and large examples. Regenerating local forecast files does not update an existing imported model run; do not rerun the importer against a populated database merely to add display statistics.

The Actions workspace also lists historical RCA tasks in a separate tab. The five decks and all 55 slides are pending individual visual review; slide text and extracted task rows remain inspectable as historical source material, but the app does not quietly promote them into verified recommendations. An approved visual review in the data source is required before an RCA task can seed a new proposal. Every saved v5 action holds source references and a cutoff-aware incident/condition snapshot. Source links target the incident row, exact weekly record, or selected RCA slide when applicable. Existing v4 actions retain their original history and require proposal editing before their unfinished workflow can continue. A prior completion remains explicitly unverified until a v5 result is reviewed.

## Viewing guide and provenance

The shared account can change the optional *View guide* between judge walkthrough, management decisions, engineering evidence and follow-up coordination. This changes guidance and a suggested entry page only. All data, actions, and account permissions remain identical; no separate human attribution is implied. Main Actions evidence displays human-readable file/date/row/slide labels, a direct source link, and a highlighted source column where available. Internal IDs remain in its technical record for auditing. An aggregate KPI's file-to-column map links to the source table; a single sample row does **not** prove the portfolio total.

## Verification and limits

Run `python scripts/validate_data.py`, `python scripts/verify_prototype.py`, `npm run build`, and `node --check api/assistant.js`. Read `docs/DEPLOYMENT_READINESS.md` for the separate live checklist. Source validation and a successful frontend build do not prove your remote migration state, authorized response from an AI provider, or saved actions in the actual Supabase project.

The supplied observations are historical. Condition History is weekly, Production is hourly, and UCI steel energy is from South Korea in 2018. The UCI source cannot be interpreted as a chemical plant meter. Five RCA documents have 55 slides pending individual visual checks. The incident portfolio is 380 source rows across 12 plant labels, while detailed condition and Production observations cover only five assets. Any time saved or business impact must be measured in a controlled validation exercise before being reported as a result. Read `docs/GATE6_VERIFICATION.md` and `docs/DEPLOYMENT_READINESS.md` for exact checks and remaining deployed verification.
